# Security Policy

## Supported Versions

Security fixes are handled for the latest published release and the current `main` branch.

| Version | Supported |
| --- | --- |
| Latest release | Yes |
| `main` | Yes |
| Older releases | Best effort |

## Reporting a Vulnerability

Please do not open a public issue for a security vulnerability.

Report security concerns privately through GitHub Security Advisories:

1. Open the repository on GitHub.
2. Select **Security**.
3. Select **Report a vulnerability**.

If GitHub Security Advisories are unavailable, contact the maintainer privately before publishing details.

## What to Include

Include enough information to reproduce and assess the issue:

- Affected DeskSwipe version or commit
- Windows version
- Install type, such as installer or portable build
- Steps to reproduce
- Expected impact
- Any proof-of-concept details, logs, or screenshots

Please avoid including secrets, personal files, or unrelated system data in the report.

## Scope

Security reports should focus on vulnerabilities in DeskSwipe itself, including installer behavior, startup behavior, local file handling, inter-process messaging, or unsafe privilege assumptions.

General bugs, compatibility reports, and touchpad detection issues should use the regular issue templates instead.
